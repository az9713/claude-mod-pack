mod-pack User Guide: Test Steps

How to load mod-pack into a running Claude Code session and test its four mods, Token Weather, Blast Radius, Cache Keeper and Wait What, in 41 steps. You do not need to exit the session.

Version 0.1.0. Written 2026-10-02, extended 2026-10-03. Nobody has yet seen these steps run on a real screen: the automated tests and claude plugin validate pass, and the /mods command is confirmed to load. Steps 1 to 41 below are the first on-screen check. Wait What (steps 28 to 41) spends model tokens: read its warning first.

1. Load mod-pack into the session

Claude Code reloads any plugin folder inside the session's hot-reload folder when the turn that changed it ends. Copy mod-pack there. If an older token-weather mod is in the same folder, move it out first. Two Token Weather mods would draw two weather rows.

Run in PowerShell. Replace <session-id> with the folder name that already exists under C:\Users\<you>\.claude\dev-mods\.

$w = "C:\Users\<you>\.claude\dev-mods\<session-id>"
New-Item -ItemType Directory -Force "C:\Users\<you>\.claude\dev-mods-disabled" | Out-Null
# only if an old token-weather folder exists in $w:
Move-Item "$w\token-weather" "C:\Users\<you>\.claude\dev-mods-disabled\token-weather-old"
robocopy "<path-to>\mod-pack" "$w\mod-pack" /E /XD .git | Out-Null
  • The copy leaves out .git, so the watcher does not scan the repository history.
  • robocopy exits with code 1 when it copied files. That is normal.
  • The mod loads when the turn that made the copy ends.
  • When you change mod-pack later, copy it again. The repository is the source, and the copy is a test build.
No hot-reload folder? Start a new terminal with claude --plugin-dir <path-to>\mod-pack instead.

2. Check that it loaded

  1. A transcript line may say that mod-pack loaded. If a hook or the module fails, a dim line names the plugin and the reason.
  2. Type /mods. You should see a list with token-weather and blast-radius, both ON, and sound: OFF.

3. Test Token Weather and the /mods command (steps 1 to 8)

StepDo thisExpected result
1Send any prompt and wait for the full answer.A weather row appears above the prompt, for example ☀ Clear 18% 184.4k / 1M ▂▂ ▲ +3.6k last turn.
2Compare its percent with /context or your status line.Both percents are close.
3Look for the next: suggestions. They show only after answers of 80 characters or more, and only if the next-steps plugin is installed.The suggestions and the weather row show together, one above the other.

How to read the weather row

PartMeaning
☀ ClearThe context window is under 25% full. Other bands: ☁ Cloudy 25–49%, ☂ Showers 50–74%, ☇ Storm 75–89%, ↯ Compact soon 90% and up.
18%Tokens in use divided by the window size.
184.4k / 1MTokens in use, then the window size. The size comes from the session, not from a fixed number.
▂▂One bar for each of the last 12 finished turns, oldest on the left. Each bar is the share of the window in use, in steps of 12.5%.
▲ +3.6k last turnThe tokens the last turn added. ▼ means the window got smaller, which happens after a compaction.

4. Test Blast Radius (steps 9 to 14)

Test on a throwaway folder only. Blast Radius holds risky commands, but you must never test it on a real folder. Create the scratch folder first, in Git Bash. You can type ! before each line to run it inside the session.
mkdir -p /tmp/mp-test/victim-a /tmp/mp-test/victim-b
echo hi > /tmp/mp-test/victim-a/f.txt
echo hi > /tmp/mp-test/victim-b/f.txt

Then send these prompts one at a time:

StepDo thisExpected result
9Use the Bash tool to run exactly: ls /tmp/mp-testNo dialog. The command runs.
10Use the Bash tool to run exactly: rm -rf /tmp/mp-test/victim-aA dialog titled Blast Radius, with a preview and the options Proceed and Cancel.
11Choose Cancel.Claude is told the person cancelled. victim-a still exists.
12Repeat step 10 and choose Proceed.victim-a is deleted.
13Type /mods off blast-radius, then ask for rm -rf /tmp/mp-test/victim-b.No dialog. The folder is deleted.
14Type /mods on blast-radius.The guard works again.

What Blast Radius holds

  • Recursive rm (-r, -rf, -fr, --recursive).
  • Windows rmdir /s, del /s and Remove-Item -Recurse.
  • git reset --hard, git clean with a force flag, git push --force, --force-with-lease and +ref.
  • git checkout -- ., git restore ., git branch -D, git stash drop and git stash clear.

It does not hold rm file, rm -f file, git clean -n, or plain git push. It is a safety net, not a permission system. Aliases, scripts that call rm, commands built from variables, find -delete, dd and redirects get past it.

5. Test Cache Keeper (steps 15 to 27)

Cache Keeper counts down how long the prompt cache stays warm after Claude's last response. From this mod on, /mods (steps 2 and 4) lists three mods: token-weather, cache-keeper and blast-radius.

The lifetime is a setting. The default is 60 minutes, the documented lifetime on a Claude subscription within plan usage. On an API key, a cloud provider or usage credits it is 5 minutes, so set cacheTtlMinutes to 5 there. To get through the steps quickly, set it to 2 (steps 18 and 19) and set it back to 60 at the end. Put it in ~/.claude/settings.json under pluginConfigs → mod-pack → options → cacheTtlMinutes, or use its row, "Cache lifetime (minutes)", in /config. The type declarations name the settings path. They say a change reloads the module. The /config row was not checked.
The compact button runs a real compaction. It does the same as /compact and spends model tokens. Test it in a session you can afford to compact.
StepDo thisExpected result
15Type /mods.A line ON cache-keeper Cache Keeper: countdown of how long the prompt cache stays warm ... with no [uses model tokens] flag.
16Send any prompt. Look at the band while Claude works, then after the answer.While Claude works: no cache row. After the answer: a row such as ⏱ cache warm 60m left · 160k tokens [ compact ], below the weather row (and below the next: suggestions, if installed). All of them show.
17Compare the tokens in the cache row with the weather row.Both show the same context size.
18Set cacheTtlMinutes to 2. Send a prompt and wait for the answer. Wait 2 minutes. The row redraws once a minute.First ⏱ cache cools in 2m in yellow, then ⏱ cache cold: next prompt re-reads 160k tokens uncached in red. No dollar amount. No toast (a 2 minute lifetime has no warm part).
19Set cacheTtlMinutes to 7. Send a prompt. Wait about 3 minutes.The row is warm for the first 2 minutes, then cools in with the minutes left. One toast, Prompt cache cools in ..., shows when the cache enters its last 5 minutes, up to 1 minute late. It does not show again for this answer.
20Send another prompt after the cache went cold.No row while Claude works. After the answer the countdown starts again from the full lifetime.
21After an answer, click compact in the cache row.The row says ⏱ compacting… with no button. When the compaction ends the cache row is gone. The transcript shows a compaction.
22Send a prompt after the compaction.The cache row comes back after the answer, with a smaller token count.
23Type /compact yourself, with the cache row showing.The row says ⏱ compacting… while it runs, then goes until the next answer.
24Type /clear.The cache row is gone until the next answer.
25After an answer, type /mods off cache-keeper.The cache row disappears at once. No toast comes later. The weather row and other plugins' output stay.
26Type /mods on cache-keeper.The row returns, counting from the last answer.
27Set cacheTtlMinutes back to 60 (or 5 on an API key).The row counts that lifetime again after the next answer.

How to read the cache row

PartMeaning
cache warm 43m leftThe next prompt, if sent now, re-reads the conversation from the cache. 43 minutes is what is left of the lifetime you set.
cache cools in 4m5 minutes or less are left. Send a prompt (it refreshes the timer), or compact.
cache coldThe lifetime is over. The next prompt processes the whole conversation again, uncached. The number is the context size after the last answer.
[ compact ]Compacts the conversation, like /compact. It has no hotkey. While any compaction runs it is replaced by compacting….

The countdown starts when the answer ends. Anthropic counts the lifetime from the start of the last request, so the row can show a little more time than is left. A model switch or a changed tool list can make the cache cold early, and the row does not see that.

6. Test Wait What (steps 28 to 41)

Wait What retells a long answer in plain words, in at most 2 short lines, in the band above the prompt. From this mod on, /mods lists four mods: token-weather, cache-keeper, wait-what and blast-radius. Wait What is OFF until you turn it on.

Wait What spends model tokens and sends your answers to the model. Each retold answer is one call to the cheapest model (the haiku alias), on your own plan. The call sends up to 4000 characters of the answer's text and reads back at most 120 tokens. Test it in a session whose answers you are willing to send a second time. The default limit is 30 calls an hour, per session. Steps 28 to 41 use about 6 to 10 retold answers.
The number of lines depends on the terminal height. The pack may use one third of the rows that the band is allowed, and the band is allowed up to half of the terminal's rows. With Token Weather and Cache Keeper both showing, Wait What gets 2 lines in a tall terminal, 1 line in a medium one, and none in a short one. The exact heights were not measured. Use a tall window for steps 31 to 35, and see step 36 for the other sizes. The limit setting maxModelCallsPerHour goes in the same place as cacheTtlMinutes (see section 5).

34Repeat step 31. As soon as the answer ends, send any new prompt before the retell shows.No retell of the old answer shows later. The late reply is dropped.

Press compact again in a few seconds. (and no compaction), or the compaction runs (the retell had already ended). Both are correct. This warns you that the compaction is a real one.

How to read the Wait What row

PartMeaning
wait what: ...The model's retell of the last answer. 1 or 2 lines. A line that does not fit the width ends with ….
wait-what: hourly limit reachedThe answer was long enough, but the hourly limit refused the call. Nothing was sent. It shows until your next prompt.
nothingThe answer was shorter than 200 characters, or Claude's turn was interrupted, or the call failed, or it is still running. A failed call shows nothing and still counts toward the limit.

The next prompt, /clear and the end of the session cancel a call that is still running. /mods off wait-what lets a running call end (15 seconds at most) and drops its reply.

7. What these tests cannot show

  • Storm and Compact soon colors. A 1M window needs 750k tokens to reach Storm. There is no cheap way to get there in a test.
  • Sound. It is silent on Windows and Linux. Only macOS plays plugin sound.
  • claude -p behavior. You cannot test the non-interactive path from inside a session. By design, Blast Radius denies risky commands when nothing can ask.
  • Cache Keeper against the real cache. The row is a countdown of a timer. Nothing here checks whether the real cache is warm, or what lifetime your account has. A model switch can make the cache cold early.
  • The compact button by keyboard. Step 21 clicks it. Focusing the band with ctrl+x then Tab and pressing Enter was not checked.
  • Dialog order. The type documentation says the Blast Radius dialog comes before Claude's own permission prompt. It has not been observed.
  • What Wait What costs. No call was measured. The size of a retell call is an estimate (about 1,000 tokens in at most, 120 out at most). Check your own usage view after the steps.
  • That the retell stays out of the transcript. The type declarations say the call has no history and the plugin adds nothing to the conversation. Look at the transcript after step 31: no retell should be in it.
  • Wait What beside the real next-steps plugin. Both can run after the same answer, each with its own call. Step 31 is the first check of the two together.
  • The row heights. The terminal heights at which Wait What shows 2 lines, 1 line or none were not measured (step 36).

8. Undo

Remove-Item -Recurse "$w\mod-pack"
# restore the old mod, if you moved one:
Move-Item "C:\Users\<you>\.claude\dev-mods-disabled\token-weather-old" "$w\token-weather"

9. What to report

Send the number of any step whose result differs from the expected result. Add a screenshot or the text you see, and any dim line in the transcript that names mod-pack.
