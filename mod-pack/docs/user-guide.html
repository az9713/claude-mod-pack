mod-pack User Guide: Test Steps

How to load mod-pack into a running Claude Code session and test its seven mods, Token Weather, Blast Radius, Cache Keeper, Wait What, Prompt Queue, Snake and Ship Gate, in 99 steps. You do not need to exit the session.

Version 0.1.0. Written 2026-10-02, extended 2026-10-03 (Ship Gate). Nobody has yet seen these steps run on a real screen: the automated tests and claude plugin validate pass, and the /mods command is confirmed to load. Steps 1 to 99 below are the first on-screen check. Wait What (steps 28 to 41, and 78 to 85 for the notes that say why no retell shows) spends model tokens: read its warning first. Prompt Queue (steps 42 to 56) sends real prompts by itself: read its warning first. Snake (steps 57 to 77) pauses and resumes by itself while Claude works: read its notes first. Ship Gate (steps 86 to 99) denies a commit and holds a push on purpose: run it on the scratch repository only.

1. Load mod-pack into the session

Claude Code reloads any plugin folder inside the session's hot-reload folder when the turn that changed it ends. Copy mod-pack there. If an older token-weather mod is in the same folder, move it out first. Two Token Weather mods would draw two weather rows.

Run in PowerShell. Replace <session-id> with the folder name that already exists under C:\Users\<you>\.claude\dev-mods\.

$w = "C:\Users\<you>\.claude\dev-mods\<session-id>"
New-Item -ItemType Directory -Force "C:\Users\<you>\.claude\dev-mods-disabled" | Out-Null
# only if an old token-weather folder exists in $w:
Move-Item "$w\token-weather" "C:\Users\<you>\.claude\dev-mods-disabled\token-weather-old"
robocopy "<path-to>\mod-pack" "$w\mod-pack" /E /XD .git | Out-Null
  • The copy leaves out .git, so the watcher does not scan the repository history.
  • robocopy exits with code 1 when it copied files. That is normal.
  • The mod loads when the turn that made the copy ends.
  • When you change mod-pack later, copy it again. The repository is the source, and the copy is a test build.
No hot-reload folder? Start a new terminal with claude --plugin-dir <path-to>\mod-pack instead.

2. Check that it loaded

  1. A transcript line may say that mod-pack loaded. If a hook or the module fails, a dim line names the plugin and the reason.
  2. Type /mods. You should see a list with token-weather and blast-radius, both ON, and sound: OFF.

4. Test Blast Radius (steps 9 to 14)

Test on a throwaway folder only. The steps below delete folders, so run them only on the scratch folder. Never point them at a real folder. Create the scratch folder first, in Git Bash. You can type ! before each line to run it inside the session.

What Blast Radius holds

  • Recursive rm (-r, -rf, -fr, --recursive).
  • Windows rmdir /s, del /s and Remove-Item -Recurse.
  • git reset --hard, git clean with a force flag, git push --force, --force-with-lease and +ref.
  • git checkout -- ., git restore ., git branch -D, git stash drop and git stash clear.

It does not hold rm file, rm -f file, git clean -n, or plain git push. It checks the text of one shell command and does not replace the permission rules of Claude Code. Aliases, scripts that call rm, commands built from variables, find -delete, dd and redirects get past it.

5. Test Cache Keeper (steps 15 to 27)

Cache Keeper counts down how long the prompt cache stays warm after Claude's last response. From this mod on, /mods (steps 2 and 4) lists three mods: token-weather, cache-keeper and blast-radius.

The lifetime is a setting. The default is 60 minutes, the documented lifetime on a Claude subscription within plan usage. On an API key, a cloud provider or usage credits it is 5 minutes, so set cacheTtlMinutes to 5 there. To get through the steps quickly, set it to 2 (steps 18 and 19) and set it back to 60 at the end. Put it in ~/.claude/settings.json under pluginConfigs → mod-pack → options → cacheTtlMinutes, or use its row, "Cache lifetime (minutes)", in /config. The type declarations name the settings path. They say a change reloads the module. The /config row was not checked.
The compact button runs a real compaction. It does the same as /compact and spends model tokens. Test it in a session you can afford to compact.

How to read the cache row

PartMeaning
cache warm 43m leftThe next prompt, if sent now, re-reads the conversation from the cache. 43 minutes is what is left of the lifetime you set.
cache cools in 4m5 minutes or less are left. Send a prompt (it refreshes the timer), or compact.
cache coldThe lifetime is over. The next prompt processes the whole conversation again, uncached. The number is the context size after the last answer.
[ compact ]Compacts the conversation, like /compact. It has no hotkey. While any compaction runs it is replaced by compacting….

The countdown starts when the answer ends. Anthropic counts the lifetime from the start of the last request, so the row can show a little more time than is left. A model switch or a changed tool list can make the cache cold early, and the row does not see that.

6. Test Wait What (steps 28 to 41)

Wait What retells a long answer in plain words, in at most 2 short lines, in the band above the prompt. From this mod on, /mods lists four mods: token-weather, cache-keeper, wait-what and blast-radius. Wait What is OFF until you turn it on.

Wait What spends model tokens and sends your answers to the model. Each retold answer is one call to the cheapest model (the haiku alias), on your own plan. The call sends up to 4000 characters of the answer's text and reads back at most 120 tokens. Test it in a session whose answers you are willing to send a second time. The default limit is 30 calls an hour, per session. Steps 28 to 41 use about 6 to 10 retold answers.
The number of lines depends on the terminal height. The pack may use one third of the rows that the band is allowed, and the band is allowed up to half of the terminal's rows. With Token Weather and Cache Keeper both showing, Wait What gets 2 lines in a tall terminal, 1 line in a medium one, and none in a short one. The exact heights were not measured. Use a tall window for steps 31 to 35, and see step 36 for the other sizes. The limit setting maxModelCallsPerHour goes in the same place as cacheTtlMinutes (see section 5).

7. Test Prompt Queue (steps 42 to 56)

Prompt Queue lets you type /q <text> while Claude works, to stack follow-up prompts. They are sent one at a time, each when the turn before it ends. A row above the prompt shows what waits. From this mod on, /mods lists five mods: token-weather, cache-keeper, prompt-queue, wait-what and blast-radius.

Queued prompts run with your permissions, and they send by themselves. When a turn ends, the next queued prompt goes to Claude as if you had typed it at that moment. In steps 42 to 56 queue only harmless prompts, such as Say the word one.. Do not queue a prompt that edits files, runs commands or sends data. In a real session, read the queue (/q) before you walk away from it. The mod itself spends no model tokens: each sent prompt is a normal turn of your session, on your plan. If you interrupt a turn with Esc, the queue pauses and sends nothing until you type /q resume.
A slow prompt for the steps. Steps 44, 48 and 51 need a turn that lasts about 20 seconds, so you have time to type. Use Use the Bash tool to run exactly: sleep 20. If your Claude Code asks for permission to run it, allow it. The queue row is drawn while Claude works. Cache Keeper's row is drawn only after an answer.

How to read the queue row

PartMeaning
queue (3): 1 fix tests · 2 update docs · …3 prompts wait. Each one is cut to 24 characters. The numbers are what /q rm <n> takes. · … means more prompts follow than the width shows.
queue paused (3): ...The queue sends nothing, and the row shows the reason: you interrupted a turn, a turn ended with an error or a refusal, you typed /q pause, or Claude Code did not accept the last prompt. /q resume sends again, /q clear drops the prompts.
nothingThe queue is empty, or the mod is off.

The commands: /q <text> adds a prompt (at most 20 prompts, 2000 characters each). /q or /q list lists them. /q rm <n> removes one. /q clear removes all. /q pause and /q resume stop and start the sending. /q add <text> queues a text that starts with a command word. Only these exact forms are commands: /q rm the old files queues that sentence.

8. Test Snake (steps 57 to 77)

Snake is a small Snake game in a pane. It pauses when Claude finishes a turn and goes on when you send the next prompt. It draws a pane of its own and takes no row of the band, so the weather, cache and queue rows keep their places. From this mod on, /mods lists six mods: token-weather, cache-keeper, prompt-queue, wait-what, blast-radius and snake. Snake costs no model tokens.

The keys work while the pane has the keyboard. The keys are w a s d (up, left, down, right), p (play and pause), r (new game) and Esc (close the pane). /snake asks for the keyboard when it opens the pane, and Claude Code grants the request when the prompt box is empty. When the last line of the pane says Keys need the pane focused: click it, or ctrl+x then Tab., do that first (step 59). A letter that appears in the prompt box shows that the pane does not have the keyboard.
The terminal must be at least 32 columns wide. The board is 16 cells of 2 columns each, and 8 rows. The pane asks for 13 rows. The snake crosses the board in about 2 seconds. When the snake hits a wall before you finish a step, press r and repeat the step.
A slow prompt for the steps. Steps 69, 70 and 73 need a turn that lasts about 20 seconds. Use Use the Bash tool to run exactly: sleep 20, as in section 7. The game pauses and resumes by itself at the end and at the start of a turn, so these steps show it.

What Ship Gate holds

  • Publish gate: git push (not --dry-run or -n), gh repo create, gh api on a pages path with -X POST, -X PUT or an -f field, and gh repo edit --visibility public. It always asks. Cancel, a dismissed dialog and a claude -p run deny the command.
  • Tested? gate: git commit when the status lists a code file and no test, type check or validator (npm test, tsc, pytest, cargo test, go test, claude plugin test, and a few more) has passed on the current tree. A commit of text files only is not held. The comment # ship-gate: skip-tests lets one commit go.
  • It does not see images, text removed in an earlier unpushed commit, a script that calls git, or a folder named with a variable. A runner that it does not know (./check.sh) needs the skip comment.

11. What these tests cannot show

  • Storm and Compact soon colors. A 1M window needs 750k tokens to reach Storm, which costs too much for a test.
  • Sound. Only macOS plays plugin sound, so Windows and Linux are silent.
  • claude -p behavior. You cannot test the non-interactive path from inside a session. By design, Blast Radius denies risky commands when nothing can ask.
  • Cache Keeper against the real cache. The row counts down a timer. These steps do not check whether the real cache is warm or what lifetime your account has. A model switch can make the cache cold early.
  • The compact button by keyboard. Step 21 clicks it. Focusing the band with ctrl+x then Tab and pressing Enter was not checked.
  • Dialog order. The type documentation says the Blast Radius dialog comes before Claude's own permission prompt. It has not been observed.
  • What Wait What costs. Nobody measured a call. The size of a retell call is an estimate (about 1,000 tokens in at most, 120 out at most). Check your own usage view after the steps.
  • That the retell stays out of the transcript. The type declarations say the call has no history and the plugin adds nothing to the conversation. Look at the transcript after step 31: no retell should be in it.
  • The notes of Wait What on a real screen. They were tested with stand-ins for the engine only. Which surfaces a real terminal session lists, what a real model error looks like, and whether the note is readable at your width were not seen. Steps 78 to 85 are the first check.
  • Wait What beside the real next-steps plugin. Both can run after the same answer, each with its own call. Step 31 is the first check of the two together.
  • The row heights. The terminal heights at which Wait What shows 2 lines, 1 line or none were not measured (step 36).
  • That /q runs while a turn runs. The plugin registers it as an immediate command, which the type declarations say runs at once in a running turn. Step 44 is the first real check. If it waits for the turn to end, the queue still works, but a prompt typed in the last second of a turn is not queued in time.
  • How a sent prompt looks. It is sent with asUser: the type declarations say Claude reads it bare, as your own words, and that the transcript still names the plugin as the sender. Step 46 is the first look. @file mentions and pasted images are not expanded in a queued prompt. Whether a queued text that starts with / runs as a command was not checked: it is sent as text.
  • Your own prompts and the queue. If you type a normal prompt while Claude works, Claude Code holds it itself. Then both your held prompt and the next queued prompt wait for the end of the turn. The order between them was not checked.
  • A draft in the prompt box. What happens to text you have typed but not sent when the queue sends a prompt was not checked.
  • Dialogs. The type declarations give no way to see whether a question dialog is open. A Blast Radius dialog belongs to a tool call inside a turn, so no turn ends while one is open and the queue sends nothing then. A dialog from another plugin that opens between turns could be open when the queue sends. It was not tested.
  • That /snake runs while a turn runs. The plugin registers it as an immediate command, which the type declarations say runs at once in a running turn. Step 69 is the first real check. If it waits for the turn to end, Snake still works, and you open it between turns.
  • Where the pane sits and how tall it is. The type declarations say Claude Code docks a pane beside the transcript in the fullscreen terminal from 110 columns, and seats it above the prompt otherwise. The plugin asks for 13 rows, and the declarations say your own size wins. How the pane, the band and the prompt share a short terminal was not measured (steps 58 and 77).
  • The keyboard. /snake asks for the keyboard, and the declarations say the request is granted only while the prompt is empty. Whether the letters reach the pane, and whether Esc closes it, is the first check in steps 59, 60 and 67.
  • The look of the board. The glyphs ██, ● and · are drawn 2 columns to a cell. A font that draws ● or · wider than 1 column shifts the board. Nobody has seen the board drawn.
  • A real Blast Radius dialog open beside the game. The automated test holds a stand-in for the dialog. Step 74 is the first run with the real one. The dialog opens only inside a turn, so the timing in step 74 is yours.
  • Toasts while Snake is open. The pane is opened without holdToasts, so the cache toast and the queue toast should show. This was not run on a real screen.
  • Ship Gate on a real GitHub remote. Steps 86 to 99 push to a bare repository on your disk. The visibility from gh repo view, the hidden credential in a remote URL, and the Pages and gh repo create dialogs are not run here. They are tested with stand-ins for the engine only.
  • How a denial reads to Claude, with other models. In a headless run (claude -p, the haiku model, 2026-10-03) the commands of steps 87, 88, 89, 91 and 92 gave the results above, and a push gave the non-interactive denial. After the denial of step 91, Claude ran npm test and committed again. Another model may stop and ask you instead. The dialog of steps 93 to 95 needs a person, so it was not run there.
  • Ship Gate beside Blast Radius. A git push --force should ask twice, Blast Radius first. Not run on a real screen.
  • The high score across sessions and a hot reload. The high score is read from the plugin store when you open the pane. A reload of the plugin drops the game's timer. The game then waits until the next prompt or key press. The steps run neither.
